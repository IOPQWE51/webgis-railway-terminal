## 小刀改进（顺手就能做）

1. **花火情报局日期过滤**：HanabiRadar tab 目前全量列出旧年份数据，可加"只看未来"开关或年份分组（半小时活）
2. **触发器与时间联动**：触发器目前只在天气到达后计算一次；`now` 状态每分钟跳动时若已跨入黄金/蓝调窗口，可重算触发器（现在只在天气/坐标变化时算）
3. **天气行加湿度/风**：`/api/weather` 已返回 humidity/wind_kph，卡上只显了云量；移动端窄卡可省，桌面卡可补
4. **附近列表空态给动作**：现在只有文案"拖动地图去别处看看"；可加一个"跳到最近的花火/收藏"快捷按钮
5. **收藏点去重**：同一坐标既有 base 又有收藏时会双条出现（如东京站）；可按 (lat,lon) 四舍五入去重，收藏优先

## 已知的体验边界

- **倒计时粒度**：每分钟跳一次（setInterval 60s），秒级刷新没必要
- **跨天**：`now` 初始值固定在组件挂载时刻，每分钟更新，跨午夜后天文条仍显示"昨天"的日落 —— 用户重开页面即恢复；如要彻底修需在 tick 里比对日期并强制重算 brief
- **`now` 依赖链**：`nearbyPool`/`card`/`trigger` 三个 useMemo 都依赖 `now`，每分钟全部重算（纯本地计算，代价可忽略，但列表会因此每分钟重建 DOM —— 目前无感，若未来点位池变大可把 `now` 拆成"日期部分"与"时刻部分"）
- **IAB 合成器**：backdrop-blur 的卡片在 ZCode 内置浏览器截图合成上有怪癖，真实浏览器无此问题（PWA/移动端实测为准）

## 视觉模型再打磨时的候选方向

- 现在卡是"上信息下列表"的竖排结构，若反馈觉得高，可把天文条收成一行可展开的折叠（首行只留日出/日落/月相）
- 附近行的 kind 徽章目前是 emoji（⭐🚉🎆），可换 lucide 图标 + 分类色点对齐项目 pink/cyan 语言
- 触发器条用项目粉点亮的设计保留，但可以给稀有度 ≥4 的规则加一次性微动效（`prefers-reduced-motion` 降级）
